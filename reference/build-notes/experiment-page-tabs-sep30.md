**THE EXPERIMENT PAGE IS TABBED (user, 2026-09-30)** in the three experiment builds of the
[[project-create-change-order]] CCO-landing repo — [[link-unlink-experiments-sep11]],
[[unpublish-experiment-sep24]], [[update-treatment-holdout-sep28]]. Under `xpHead` come two tabs:
**Experiment meta** (the grey `xpMeta` attribute card) and **Linked experiences** (`xpToolbar` +
the experiences table). Applied to every canvas that used to render `xpMeta` + `xpToolbar` +
table (xpDetail's unlink/link/treatment blocks, upDetail, the mvExp/mvMulti task canvases).
The search-results lists (`xpSearch`, `upSearch`, the mv landing lists) are NOT tabbed — they
have no meta card.

- Shared helper `xpBody(state, metaHtml, listHtml)` right after `xpToolbar` in each app.js;
  markup is `.tabs.tabs--exp.xpTabs` (same chrome as the experience drill-down tabs) with
  `[data-xptab]`; CSS `.xpTabs{margin-top:-4px;margin-bottom:24px}` in each index.html.
- **TAB RULES** (user, 2026-09-30, three notes): **opening an experiment lands on Experiment
  meta** ("from search results if i open an experiment it should land on experiment meta. then
  i navigate to experiences") — both intakes, search and direct. **THE TAB NEVER CHANGES ON ITS
  OWN**: "when we create a draft post selections on linked experiences tab ... don't refresh to
  bring to meta tab", and "if I trigger unpublish from meta tab, that should stay, if from
  experiences tab, then that. don't change randomly" (unpublish and link make no selection, so
  the ask is typed and sent from whichever tab is showing). Implemented as LOCK-IN: `xpBody()`
  writes the tab it rendered back into `state.xpTab` (`st.xpTab = t`), so a default becomes the
  user's tab from then on and every `*Base()` carries it. A first version flipped to the list
  once a flow key (`ul/lk/tt/up/mv`) was in flight — that moved the unpublish intent, typed from
  meta, onto the list; REMOVED. The only default left is for a state that arrives without a
  tab (fresh open, arrow-key jump into a step literal): `selected` non-empty → list, else meta.
- **THE HIGHLIGHT-CHANGES BAR IS THE PAGE FOOTER, NOT THE LIST'S** (user, 2026-09-30: "action
  bar with highlight changes is missing" on the meta tab). In the treatment build it was glued
  onto `ttable`; now emitted after `xpBody(...)` so it shows on both tabs — the meta tab has a
  highlight of its own (the holdout value), and the toggle works from there.
- `state.xpTab` is UI-only: the click handler (generic, at the tail of `wire()`) uses
  **`render(name, {...state, xpTab})`, never `go()`** — `go()` clears the flow's timers and a
  tab click mid-loader would kill the loader. It is **carried by EVERY `*Base()`**
  (`if(st.xpTab!==undefined) b.xpTab=st.xpTab;`), same idea as `verOpen`. First pass anchored
  the carry on the `verOpen` line and MISSED `ulBase()` (which never carried verOpen), so the
  tab snapped back at `done` — patch every `*Base()`, not just the ones that look alike.
- Step nav (`FLOW_STEPS`/`stepIndex`) needed no change; arrow keys reset to the default tab
  because step states are literals without `xpTab`. Autopilot never clicks experiment rows.
- Generated by regex over the `${xpMeta(...)}/${xpToolbar()}/${table}` triples: a ternary
  table expression (`c==='pubTo' ? skeleton : table`) MUST be parenthesised after
  `xpToolbar() +` or `+` binds first and the toolbar vanishes. Verified live in all three
  builds (typed asks, loaders, selection retained, holdout highlight on the meta tab).
- Cache-busters after this work: link-unlink v168, unpublish v9, update-treatment v42.
